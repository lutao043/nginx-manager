## 修复：exe 运行中偶发「页面打不开」（API 正常但页面 404）

从 v0.6.3 起，长期运行的 exe 不会再出现该问题。

### 根因

单文件 exe 每次启动会把前端页面资源解压到系统临时目录（`%TEMP%\_MEI*`），运行期间从那里读取文件或 DLL。当 Windows 磁盘清理 / 存储感知 / 管家类软件在运行期间清掉该目录后，进程仍然存活、所有 API 正常应答，但页面请求全部返回 404（`{"error": "Not Found"}`）——表现为「服务没挂，但网页打不开」。重启 exe 之所以能临时恢复，只是因为重新解压；下次清理周期一到仍然复发。

### 修复内容

- **前端资源持久化**：exe 启动时把前端资源落盘到用户数据目录（`%APPDATA%\nginx-manager\frontend\v0.6.3\`），静态文件改为从持久副本提供，临时目录再被清理也不受影响。副本按版本分目录管理、旧版本自动清理、副本损坏自动重建、落盘失败自动回退原路径。
- **可观测性**：启动时打印 `[前端] 资源目录: ...`；静态资源缺失时控制台输出一次性告警并说明真实原因；`GET /api/status` 新增 `frontendOk` 字段，浏览器里一眼确认前端资源健康度。
- **契约同步**：API.md 补充 `frontendOk` 字段说明。

### 使用提示

- Windows：下载 `nginx-manager-v0.6.3.exe` 替换旧版即可。旧进程仍在运行时，直接启动新 exe 会由单实例机制自动接管旧实例。
- 启动后看到 `[前端] 资源目录: ...\nginx-manager\frontend\v0.6.3` 即表示资源已持久化，问题不再复发。
- 源码运行不受此问题影响，无需额外操作。
