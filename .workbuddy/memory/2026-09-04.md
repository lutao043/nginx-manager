## 服务假死修复（用户报「程序会自己断开，需重启才能访问」）
- 用户截图是 WinError 10053 traceback（客户端断开时的无害日志），但深挖发现真实 bug：
- **根因链**：`/api/status` 每次跑 nginx -v + PowerShell Get-CimInstance/tasklist（最坏 20-45s）→ 前端 10s 轮询堆积 → 挂起连接超 ThreadingHTTPServer 默认 listen backlog（**仅 5**）→ 新连接被拒 → 服务假死

  - `/api/status` 加 15s TTL 缓存 + `_status_lock` 串行锁（同刻只跑一次检测子进程）
  - nginx start/stop/reload/restart、`_api_settings_put` 后 `_invalidate_status_cache()`
- **验证**：py_compile 过；预览模式并发 10 请求全 200；断开 x10 零 traceback；每轮破坏后服务存活
- 测试坑：Bash tool 普通命令的 `&` 后台进程随命令结束被回收 → 用 run_in_background + TaskStop；curl 被本机 HTTP_PROXY 劫持返回 502 → 加 `--noproxy "*"`

## 修复空 nginx.pid 文件（commit d63d58a）
- 用户截图报错：`nginx: [error] invalid PID number "" in "D:\soft\nginx-1.22.1/logs/nginx.pid"`
- 根因：nginx 异常退出（崩溃/强杀/断电）后 pid 文件残留为空或含非数字内容；nginx 启动/重载时读此文件报错
- 修复：新增 `_clean_stale_pid_file(prefix)` 静态方法，在 start/reload/restart 前调用
  - 空文件 → 删除
  - 仅含空白/换行 → 删除
  - 含非数字内容 → 删除
  - 有效 PID 整数 → 不动
  - 文件不存在 → 静默跳过
- 单测 5 场景全过；py_compile OK
